# Final tasks the team must complete before submitting

1. **Publish the GitHub repository.** The competition demands a GitHub repository link. Ensure your own team understands, reviews and independently develops the entry under the contest's originality rules. Do not commit API secrets, real invoice personal data, or `.env`.
2. **Provide real bank quote evidence for your demonstration pair.** Use the exact provider, customer type, sending country, destination country, payment purpose, quote timestamp, fee and expiry. The package does not contain any live verified offer; the example evidence uses synthetic quote entries that are transparently labeled.
3. **Verify every country rule for the claimed functionality.** Regulator home pages are not enough for legal eligibility. Get bank/official source review before treating real provider corridors as permitted.
4. **Run MySQL setup (`docs/MYSQL_SETUP.md`) and the software end-to-end on your own laptop.** Check `http://127.0.0.1:8000`, fetch reference FX, enter real program details, upload a permissioned invoice PDF and confirm the plan.
5. **Record the required real demonstration.** Use `docs/DEMO_VIDEO_SCRIPT.md`; show actual sandbox logs while capturing the live application. Keep the optional standalone demo video at or under 5 minutes.
6. **Review security report and replace demo secret** if running beyond private localhost. Never deploy the current single-user local MVP as a financial product without proper authentication and compliance review.
7. **Perform original-team review, license check and test rerun.** Attach quantitative performance screenshots or a test-results report; do not fabricate scores.
8. **Keep presentation under 10 minutes.** Source deck has 10 slides. Practice and tighten if needed.
9. **Submit before the official deadline.** Deadline Oct 20 2026 23:59 Beijing time, equivalent to Oct 20 21:59 Bangladesh time.
